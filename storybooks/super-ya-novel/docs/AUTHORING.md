# 每集兩份作品的製作規格

唯一寫作範本：`content/books/kiki/source.md`。這是完整悄悄話稿，不能把其篇數或與理解單元的對照關係當成固定格式。其他既有故事僅維護相容性。

## 讀稿先行

保存原始 Markdown 的完整位元組及 SHA-256；把原逐字稿、得到大腦摘要分開判讀。逐字稿優先，摘要不作新增情節的證據。預告、購票宣傳不進作品。

事件表每列包含 `time`（原稿時間）、`event`、`quote`（原話）、`status`（明示／推測／不明）、`turningPoint`、`expectation`、`result`。不明細節採中性描述；影響關鍵情節的疑問先問使用者，列在 `editorial.unresolvedCritical`，不能帶著疑問上架。

琪琪必守：想挨罵不等於故意折花；泥巴畫在「一件東西」上；追球跑向馬路是意外發展，不能列為第四個計畫。不要以責罵證明愛，也不要把安全提醒與說話音量混為一談。

## 分開寫作

**閱讀理解**：依理解目標劃分可獨立讀懂的故事短文，不截取缺乏前提的一段。每單元三題：明示訊息／順序 → 原文根據 → 原因、心情、期待或反差。第二題使用 `type: evidence`；每題有正確答案、文章段落索引、兩層提示及解析。推論必須指出支持它的文字，不把猜測當事實。選項須合理，不用荒謬答案送分。最後自由表達為選填、不評分；沒有「想法短文」或固定加題。

**時光悄悄話**：保留小說式連續段落和第一人稱。從具體動作、原話、意外開始：「那一天」回看 → 現在的巧虎承認感受、猜想或漏看 → 拆開混淆的兩件事 → 依據與推論限制 → 邀孩子補充／不同意 → 自然回故事。陪讀部分以 `presentation.guideRanges` 標示，不另加章末選項聊天。避免反覆說理、假定角色內心、強迫原諒。

兩份目錄獨立規劃，數量可不同。每份有完整起承轉合，不用同一篇號對應另一模式。篇幅由內容決定，不硬湊九篇或固定字數。已核定琪琪全文不重新改寫。

## 校對與交稿

繁體中文、臺灣用語。詞語、詞義、臺灣注音分開校對；裝置朗讀優先 zh-TW。`readings.phrases` 為逐字 offset 的語境注音修正，多音字和輕聲不能只信自動轉換。執行 build 後逐篇看 `output/annotation-review.txt`，記錄人工檢查範圍，不把自動檢查稱為人工校對。

交付原稿、事件表／疑問、兩份完整內容、答案根據、詞義、注音修正與校對摘要。摘要列篇數、正文實際字數、各篇思考主軸、原稿依據、推論及待確認處。正文、注音、題目與證據各自可校訂；不加入即時 AI 或麥克風。

## 工具流程

1. 依 `docs/submission-template.json` 完成交稿檔；問題／證據形狀參考琪琪 `content/practice.json` 的 `kiki` 部分。
2. `node scripts/validate-content.mjs 交稿.json`：檢查兩模式完整性、三題、兩提示、證據索引、答案、陪讀範圍、原稿與校對摘要。
3. `node scripts/import-episode.mjs 交稿.json --preview`：只產生 `output/drafts/<id>`。啟動命令見工具輸出；從預覽書架檢查兩模式。預覽以獨立儲存前綴及記憶體雲端介面運作；不讀寫正式 API。預覽 meta 讓去掉 query 的連結也不會寫正式進度。
4. 向使用者提供完整預覽及校對摘要，取得上架確認。
5. 確認後才執行 `--publish` 加到本機正式清單；既有識別碼不能覆寫。Build → Node tests → 歷史及新增瀏覽器流程 → Cloudflare 部署 → 從根網址核對版本及入口 → commit/push。

工具只能驗證結構，不能證明小說品質或推論成立。交稿者須逐題人工核對原文與干擾選項，逐篇核對故事事實、語氣和注音。新增圖片先核對出處與本集情境；沒有圖片也可用完整文字預覽。

## 穩定識別與紀錄

清單 `content/library.json` 提供資料路徑，build 自動推導兩模式篇數及 Worker 白名單。篇章 id 與理解 `s1`、`s2` 一經上架不可重新分配；若須重排已上架內容，先設計舊 id 遷移。新作不共用既有書的 storageKey。

舊想法短文原稿保存在 `content/legacy-practice.json`，作答／筆記繼續留在既有 D1 文件。父母模式顯示為舊版紀錄，排除目前必做題數。不刪資料、不變更資料庫 schema。

琪琪與新作的理解來源分為 `practice-passages.json`（文章）、`practice-questions.json`（題目選項）、`practice-answers.json`（正解、提示、證據、解析）。清單的 `practiceSource` 指定來源；build 合併為瀏覽器用的 `dist/practice.json`。完整悄悄話 `source.md` 與排版解析 `story.json` 分開；`evidence.json` 保存逐字稿依據與校訂摘要，注音修正獨立於正文。`content/practice.json` 保留相容匯出快照及舊故事資料；有 `practiceSource` 的作品以分檔為準。不要再執行舊的 `import-practice.mjs` 來製作新集數。
