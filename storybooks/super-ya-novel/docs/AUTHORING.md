# 每集兩份作品的製作規格

完整悄悄話的厚度參考：`content/books/kiki/source.md`。後續新稿以本文件中使用者 2026-10-17 的心理、代價、放下、小怪獸與兒童語氣修訂為優先，不受既有篇數或整段故事後才整段陪聊的版型限制；閱讀理解的單元也不必與悄悄話一一對應。已核定琪琪全文及其他既有作品保留，獲准重寫時再依新規格處理。

## 讀稿先行

### 2026-10-20 試讀優先：每個事件可以獨立展開

使用者後續明確修正：每個動作、每句話都可以各自討論；不用先拼成完整故事、固定篇數或補足每段的前因後果。先列可討論的事件點，與使用者確認後逐點展開。這項要求優先於下文舊版「每份有完整起承轉合」的限制。

事實仍須核對說話人、動作、順序及指涉。只有在解釋人物為什麼這樣做時，才依已知證據核對期待、阻礙與可能心理；不能為套用因果分析硬補動機。直接討論一個行為如何影響他人、選擇的代價或能做什麼，也可以是一整篇。

兒童試讀稿只呈現巧虎的故事回想與分享。成人分析的目的、概念、選材理由和校對說明放在獨立 review 檔；不能只把成人分析換成第一人稱。用自己的朋友、玩具、心裡冒出的原話和具體動作說明，語意短段落、故事與分享交錯，一次聚焦一個事件。推測和生活假設清楚標明；不把感受本身等同攻擊，討論的是吼叫、責怪、動手等實際行動及後果。

第一份五事件試讀位於 `editorial/child-trial-2026-10-20/`，使用現有注音與閱讀介面產生隔離的本機預覽；不替換正式作品、題目或孩子進度。

2026-10-20 後續授權：使用者接受前五篇節奏，要求完善全篇並取代正式書架第一個 SUPER YA。完整四十篇見 `content/books/super-ya-events/source.md`，新增三十五篇；原五事件檔保留作核定開頭存檔。新悄悄話使用獨立版本進度；原閱讀理解、其他作品與歷史文件保留。重複書架入口收起，既有網址提供相容導向。

2026-10-21 測試偏好：文章與小幅介面修改只做受影響內容／流程及直接相關回歸；共用存檔或核心導覽改動才擴大，不讓無關的整套測試拖延交付。

保存原始 Markdown 的完整位元組及 SHA-256；把原逐字稿、得到大腦摘要分開判讀。逐字稿優先，摘要不作新增情節的證據。預告、購票宣傳不進作品。

事件表每列包含 `time`（原稿時間）、`event`、`quote`（原話）、`status`（明示／推測／不明）、`turningPoint`、`expectation`、`result`。不明細節採中性描述；影響關鍵情節的疑問先問使用者，列在 `editorial.unresolvedCritical`，不能帶著疑問上架。

琪琪必守：想挨罵不等於故意折花；泥巴畫在「一件東西」上；追球跑向馬路是意外發展，不能列為第四個計畫。不要以責罵證明愛，也不要把安全提醒與說話音量混為一談。

### 場景與因果先核對，再做心理分析

每一場先寫清楚「發生什麼 → 每個人原本期待什麼 → 期待在哪裡受阻 → 各人如何理解及歸責 → 因而說了什麼、做了什麼」，最後才採用心理學概念，分析選擇、代價及可試的做法。核對每句話的說話人、時點、對象、代名詞指涉及前一句刺激；事實與推論分開標示。不能先挑面子、自我保護等概念，再把人物套進去。

完成分析必問：「是否解釋了這個人為什麼偏偏在這個時候，為這件事生氣？」僅解釋一般人為何會生氣，尚未完成。每項背景須說得出它如何影響眼前事件；無關背景即使真實也應刪除。一般心理、次要可能與本場直接起因須區分，不可用深層猜想取代已知的具體動機。

SUPER YA 反例：吉吉受邀卻沒搭到，等大家回來以為輪到自己，得知至少三天後才能再玩而抗議；卡歐怪球、吉吉怪裝置、卡歐反駁設計。先理解期待落空、等待與互相歸責，再探討防衛。此處「沒徹底修好」是對 SUPER YA 相關裝置的指責，與娃娃屋無關；不能用卡歐會修娃娃屋來說明他為什麼生氣，也不能僅因他替設計辯解就把面子當作唯一主因。

另一個反例：開場不受控球先撞上卡歐的臉、使他倒地，才有卡歐請收球與吉吉說可以打發無聊的反應。寫稿漏掉撞人，就會把具體的收球理由誤寫成泛泛的「不要亂碰」，再硬套不存在的巧虎等不及伸手情節。影片後段巧虎拿著吉吉的袋子，也是球後來出現的相關動作，不能因只抄對話而漏掉；但不能由拿袋子推定巧虎未收好或應負全責。原逐字稿的同一「說話人」標記合併多位角色，遇到角色、對象與動作關鍵處必須核對影片，不可把標記直接當人物身分。先看已發生的後果及誰受影響，再從該場行為選擇心理探討角度。

## 分開寫作

**閱讀理解**：依理解目標劃分可獨立讀懂的故事短文，不截取缺乏前提的一段。每單元依一年級孩子的理解目標安排題數，不固定三題；涵蓋明示訊息／順序、原文根據、原因、心情、期待或反差，有不同且有根據的目標便可加題，不用重複問法湊題。第二題使用 `type: evidence`；每題有正確答案、文章段落索引、兩層提示及解析。推論必須指出支持它的文字，不把猜測當事實。選項須合理，不用荒謬答案送分。最後自由表達為選填、不評分；沒有「想法短文」或固定加題。

**時光悄悄話**：保留小說式連續段落和第一人稱。寫作前依下節分析具體原話與行為背後的心理，再轉成孩子能懂的解釋與做法。正文採「一小段劇情 → 巧虎陪聊、解釋 → 接回劇情」交錯，不先濃縮整段故事再接長篇說理。陪讀部分以 `presentation.guideRanges` 標示，不另加章末選項聊天。保留孩子補充／不同意的空間，避免假定角色內心、強迫原諒。

兩份目錄獨立規劃，數量可不同。每份有完整起承轉合，不用同一篇號對應另一模式。篇幅由內容決定，不硬湊九篇或固定字數。已核定琪琪全文不重新改寫。

## 2026-10-17 使用者校訂：心理、人性與放下

這是後續悄悄話的長期寫作要求，適用於新稿及獲准重寫的內容；不因記錄本規格而自動改動正式作品。

1. **先分析，再寫給孩子看。** 用兒童心理學與人物分析的視角，找出值得探討的原話、行為、期待、害怕與選擇；寫清楚心理如何導向行為，核對故事證據、替代解釋及不確定處。再以兒童故事編輯的方式重新寫成巧虎陪孩子回看的文章。不可只把劇情再說一次、連續提問，或只把成人分析換成第一人稱。
2. **可以直接解釋心理學。** 使用者希望理解「為什麼人會這樣」：如怕被罵、怕朋友不喜歡自己、想保護自己、覺得不公平、急著證明自己沒錯。可以說明這是許多人都會出現的念頭，並具體示範接下來怎麼做；不要把某種心理說成所有人的必然動機，不以理論診斷角色。引用心理學概念或研究時先查核可靠來源，成人分析與兒童正文分開保存。
3. **心理說明必須有因果。** 以娃娃屋為例，要解釋「擔心被責怪或失去朋友 → 急著指出別人的責任 → 對方也想保護自己而反擊 → 越吵越兇」，同時保留真被冤枉、記憶或觀察不同等可能。單寫「他們生氣、搶著說話、沒有聽進去」不算解釋。
4. **理解後，要有可做的事。** 接住害怕或委屈後，提供符合當下情境的話和行動：停一下、如實說出自己做過和不確定的事、澄清被誤會的部分、關心物品主人、一起修理或求助。理解反應常見，不等於鼓勵推責；不要求孩子承認未做過的事。
5. **允許佛學觀點，長期引導「放下、不執著」。** 這是使用者明確希望孩子逐步理解的主軸，可以說出概念，並以生活情境解釋。此例著重看見「反覆爭輸贏、非要證明全是對方的錯，無助於修好娃娃屋，也耗掉時間」，練習鬆開這個念頭，把力氣用在眼前能做的事。孩子的感受、事實澄清、責任及必要界線仍須被照顧；不以「放下」要求壓住情緒、容忍傷害或立刻原諒。不硬套每段劇情；涉及佛學教義或引文時查核原典及可靠出處。
6. **保留對處理方法本身的探討。** 巧虎邀大家看機器人的做法，值得分析動機、可能作用、每位朋友的反應及適用時機；不因朋友仍生氣就草率判定失敗，也不替意外的兜風安排預謀。
7. **內容與排版一起降低難度。** 以可想像的動作、原話與生活經驗解釋；按語意分行、留白，陪讀用引用區呈現，換話題有明確分隔。每小段先確定「到底想讓孩子理解什麼」，不用空泛比喻、成人慣用語或大量假設繞圈。深度來自理解人，並非增加抽象句子。
8. **每個選擇都看得到代價。** 使用者希望孩子理解「任何東西都要付出代價」：討論行為時要具體呈現得到什麼、付出什麼、放棄了哪個機會，涵蓋眼前與後續結果。爭吵可能暫時讓自己發洩、覺得沒有任人責怪，同時耗掉遊玩或修理的時間、心力及朋友相處的機會；放下爭輸贏，可能要承受沒有立刻得到認同、沒有最後一句話、仍覺得不甘心，也可能讓自己有時間處理問題、重新一起玩。依本集證據選擇實際發生的後果，假設須明示；不保證每次爭吵都傷害友誼或放下就立刻和好。代價使用孩子懂的話，例如「這段時間本來能一起做什麼」「我現在最捨不得放掉什麼」。不把代價當成處罰，不把放下寫成沒有難處，也不要求以承擔不實責任、放棄安全或壓住情緒交換和平。辨別必要的澄清、表達與反覆爭輸贏。

## 校對與交稿

### 補充的陪讀聲音與情緒比喻（2026-10-17）

- **巧虎是回想後分享。** 使用者明確刪除「我想陪你想一件事」這種帶活動、出題的口吻。以「我後來想……」「我發現自己……」分享自己的理解，保留孩子自然聯想的空間；不連續要求孩子回答，也不替孩子編出回應。
- **最新確認的兒童語氣。** 深的概念可保留，句子從巧虎自己的朋友、玩具、時間與感受說起。用「我的朋友可能很難過」，避免泛稱後接抽象結論。「婷婷的娃娃屋還壞著」改為「他們吵了這麼久，婷婷的娃娃屋還是沒修好」；「這兩件事都需要被看見」改為「我知道我的朋友不是故意的，可是我的玩具真的壞了，我還是好難過」；「照顧自己的時間和心情」改為「我想先去玩，不想跟著一起生氣」。減少每小段末尾再歸納一個道理。
- **先不介入也值得認真分析。** 使用者傾向朋友在氣頭上時先不加入評理，避免把自己捲入、大家更困擾。依情境說清楚介入與不介入的得失，保留關心、邀請、退開及必要求助，不把立即勸和當唯一正解。巧虎不用負責讓每位朋友或大人立刻開心。
- **加入「情緒小怪獸」。** 生氣、害怕／恐懼、嫉妒，以及不想念書、想逃開、非得吵贏等念頭或衝動，都可用不同小怪獸來比喻。這是作品的創作比喻，借用觀察身心、無常、不執著的佛學方向，不把「七情六慾都是怪獸」當作佛經原句，也不把「無我」解釋成另外藏著一個固定的真正自我。
- **小怪獸出現 → 聽懂它在急什麼 → 看它催我做什麼及代價 → 自己選下一步。** 例如「怕被罵的小怪獸」催我先怪朋友，「一定要贏的小怪獸」催我再吵一句。要解釋引發它的具體事情，承認許多人都有這些反應，再示範停一下、澄清、求助或處理問題。孩子可理解為「我現在很生氣，但生氣的聲音不用替我決定每個動作」。保留巧虎也會被情緒催著走、需要練習的空間。
- **情緒可被看見與理解。** 不把小怪獸寫成孩子是壞人、不乖或必須消滅的敵人；不以「別被控制」要求孩子立刻不生氣、不害怕。害怕也可能提醒危險；不想念書可能涉及累了、看不懂、怕答錯或想玩，要依情境查明，不一律歸為懶惰。不推卸行為責任給怪獸，也不承諾一個方法立即消除情緒。
- **使用者進一步確認：看見、溝通、減弱影響，並承擔行為代價。** 小怪獸的出現往往無法事先阻止；練習認出它、理解它在怕／想什麼，和它說話，暫停、求助或選擇別的做法，逐步減少它對行為的影響。目標是帶著仍在的情緒選擇行動，不能把「控制」寫成必須立刻沒有情緒。
- **行為仍是自己做的。** 「小怪獸叫我這樣做」不能免除行為責任。以故事中具體且合乎比例的後果說明代價：反覆爭吵耗掉時間、讓人難過或暫時不願一起玩；損壞物品需要參與收拾、修復與道歉；拖延可能壓縮可玩的時間。後果須有依據或明示為可能，不加造懲罰、羞辱或威脅，不以情緒本身收取代價。讓孩子理解願不願意練習影響選擇與後果，同時保留尚未學會、情緒太強而需要協助的情況；不能直接從一次失控判定孩子不願意。失控後仍可停下、求助、修補，也須逐步學會負責。
- 查核依據：[SN 22.59 無我相經英譯](https://www.dhammatalks.org/suttas/SN/SN22_59.html)（五蘊無我、無常與不執取；與本作小怪獸比喻分開）；[美國兒科學會情緒引導](https://www.healthychildren.org/English/family-life/family-dynamics/Pages/helping-little-people-manage-big-feelings.aspx)（辨認、命名及接納感受，區別感受與行為）。

繁體中文、臺灣用語。詞語、詞義、臺灣注音分開校對；裝置朗讀優先 zh-TW。`readings.phrases` 為逐字 offset 的語境注音修正，多音字和輕聲不能只信自動轉換。執行 build 後逐篇看 `output/annotation-review.txt`，記錄人工檢查範圍，不把自動檢查稱為人工校對。

交付原稿、事件表／疑問、兩份完整內容、答案根據、詞義、注音修正與校對摘要。摘要列篇數、正文實際字數、各篇思考主軸、原稿依據、推論及待確認處。正文、注音、題目與證據各自可校訂；不加入即時 AI 或麥克風。

## 工具流程

1. 依 `docs/submission-template.json` 完成交稿檔；問題／證據形狀參考琪琪 `content/practice.json` 的 `kiki` 部分。
2. `node scripts/validate-content.mjs 交稿.json`：檢查兩模式完整性、各單元題目、兩提示、證據索引、答案、陪讀範圍、原稿與校對摘要。
3. `node scripts/import-episode.mjs 交稿.json --preview`：只產生 `output/drafts/<id>`。啟動命令見工具輸出；從預覽書架檢查兩模式。預覽以獨立儲存前綴及記憶體雲端介面運作；不讀寫正式 API。預覽 meta 讓去掉 query 的連結也不會寫正式進度。
4. 向使用者提供完整預覽及校對摘要，取得上架確認。
5. 確認後才執行 `--publish` 加到本機正式清單；既有識別碼不能覆寫。Build → Node tests → 歷史及新增瀏覽器流程 → Cloudflare 部署 → 從根網址核對版本及入口 → commit/push。

工具只能驗證結構，不能證明小說品質或推論成立。交稿者須逐題人工核對原文與干擾選項，逐篇核對故事事實、語氣和注音。新增圖片先核對出處與本集情境；沒有圖片也可用完整文字預覽。

## 穩定識別與紀錄
