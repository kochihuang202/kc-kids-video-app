## 架構確認後的第一個開發切片

1. 以官方設定啟用 MCP 唯讀模式，連線 initialize、tools/list，保存不含 token 的工具 schema；只呼叫確認為查詢的工具。先讀 workspace 身分，禁止會跳轉／排版或寫入的呼叫。正式庫只讀；測試資料建立在隔離空間。
2. 以本輪 schema 和官方輸出共同建立物件清冊，補日記、待辦、網頁／便簽／形狀、塊引用、PDF 定位、影音、歷史、收藏與側欄排序，核對附件實體與 useLink。
3. 產生具代表性的隔離測試庫：共享卡片跨兩板、富文本、標籤屬性、PDF 高亮、圖像、影音定位、Mindmap 與連線。來源格式無法由官方 API 建立時，先確認支援的 import 方式，不直接改正式庫。
4. 做完整匯出／校驗與官方隔離回載。成功才決定是否值得進入儲存 adapter；失敗先定位是 API 缺資料、格式缺失或官方 importer 重建 ID。

## 方案決策點

- A 若只能完成「旁路明碼鏡像」，明列其未滿足明碼權威儲存；不以容易完成為由降低使用者 P1/P2。
- 取得官方 storage extension／合作授權後，優先 B 的最窄 adapter seam；不修改授權、更新驗證或技術保護。
- 官方不提供邊界且完整 P1/P2 必須成立時，才重新估 C，先驗證替代白板性能與資料相容，不能先做漂亮 UI 再補遷移。

## 最少人工驗收

程式自動核對 ID／引用／檔案 hash、交易恢復及效能。使用者集中驗收：混合白板真實操作、中文 IME 連續建節點、雙機切換及衝突保留、空資料夾完整恢復。未改模組不每次重測全部，但儲存／Undo／引用／附件解析相依功能必須回歸。

不承諾目前無證據支持的人日或保留比例。M2–M5 工期應在 M1 的介面與授權 gate 解除後估算。
