## 捲動擷取：已核對的實際流程

1. `0x01568ca8`／`0x01568e20` 判定標準垂直捲軸或獨立 `ScrollBar` 控制項。`0x01568f7c` 比較捲動前後的位置，標準分支送出 `WM_VSCROLL`／`SB_LINEDOWN`。
2. `0x01566b6c` 先取一張圖，再送捲動。無可用標準捲軸，或標準捲動回報零位移時，有滑鼠滾輪 `-120` 的備援分支。一般滾輪分支等 300ms，後面另加可設定的延遲。
3. `0x01567c88` 比較尺寸、格式與逐列內容。相同時回傳零位移。
4. 精確搜尋：取前圖 `x=50`、`y=H-100`、寬 `W-100`、高 `50` 的影像帶；在後圖依序試 `y=H-100-d`，`d=0..300`。這是逐像素搜尋。
5. 找不到精確接點後，改用寬 `W-100`、高 `floor(H/2)` 的區塊，從 `x=50`、`y=floor(H/2)` 起，再逐個候選位移比較。
6. 後備比較呼叫 ImageEn 的 `TImageEnProc.CompareWith`：`0x009e0398 → 0x009e0c60 → 0x009e0788 → 0x009e047c`。目前使用的預設模式先算整數亮度，再用平均亮度差評分：

   ```text
   Y = (21 × R + 71 × G + 8 × B) div 100
   similarity = 1 − mean(abs(Y_before − Y_after)) / 255
   ```

   權重由 `0x0098d0b4` 讀取設定欄位，並已在原程序核對。這些權重是本次觀察值，不能假設所有版本都固定相同。另有彩色／透明度分支，本輪沒有把它們當成目前擷取呼叫的預設路徑。
7. 比較值等於 1 時立即採用；否則保留最佳值與位移。這段未看見第一版替代程式的「0.90 才接受」門檻。後備比對成功會設定旗標；下一輪旗標及上次位移都有效時，有直接沿用該位移的分支。
8. `0x01567148` 依位移增加長圖高度，從當前畫面底部預留 50px 上方取新增區域。`0x01567b64` 比較本次新增片段和上一片段，重複片段不繼續附加；計數超過三次時結束。
9. 位移為零、`-1`、取消旗標，以及重複片段都有停止分支。不能把每個停止值都說成真的碰到內容底部。
10. `0x0156692c` 獨立輪詢 Esc，間隔參數為 100ms，寫入取消旗標；主流程與候選搜尋都檢查它。正常收尾另有補回底部 50px 的分支。取消時不走這個補回分支，已完成內容仍交回編輯器。

### 使用者失敗影像重播

失敗案例的 viewport 是 539 × 720。前一張從 `partial.png` 最後 720 列重建，因此有明確的證據界限。

- 精確影像帶：找不到完全相同的接點。
- 還原後備流程：最佳位移 **100px**，相似度 **0.9158805912**。
- 次佳是 99px，分數 0.8761067687；下一名 101px，分數 0.8754083106。
- 說明：這個案例需要走後備比較。第一版自行寫的 RGB 全域判定回報信心約 0.641，因其門檻而停止；兩種分數定義不同，不能拿數值當作同一種精度量尺。

`scroll_model.py` 是這段預設比對路徑的獨立驗證模型，使用 NumPy；本機重播另外使用 Pillow。模型明確限制 viewport 寬 >100、高 >=600；更小的影像可能涉及原版裁切邊界，尚未宣稱等價。

```powershell
python picpick-replacement/research/test_scroll_model.py
python picpick-replacement/research/scroll_model.py <partial.png> <unaligned-frame.png>
```

模型不執行 PicPick，也沒有改進、取代原版演算法的宣稱；它用來確認反編譯解讀能重現影像選點。

## 圖片編輯與分頁

- 編輯文件 `TfrmImage` 繼承 `TdxForm`；主窗 `TfrmMain` 繼承 `TdxRibbonForm`。
- `0x0198b674` 建立圖片文件、指定影像和路徑，建立分頁並將文件視窗識別寫進分頁資料。
- 圖片由 `TImgView32`／`TBitmap32` 顯示，標註有獨立的 `TDrawObjLayerBase`（繼承 `TBitmapLayer`）及 `TDesignerLayer`。
- 19 個繪圖類別包含線、貝茲曲線、多邊形、星形、箭頭、文字基底、矩形、橢圓、弧、菱形、放大鏡、編號與圖章。建立、繪製、旋轉及設計器滑鼠處理均有函式證據。
- `TfrmImage +0x4dc/+0x4e0` 保存各自的復原／重做狀態。圖片的 MouseDown、MouseMove、MouseUp，會操作目前圖層與工具狀態。
- `0x015a7224` 寫入文件 `+0x4da` 的修改旗標；`0x0199a660` 找到對應分頁，依旗標選擇圖示索引 `0xa6`／`0xa7`。尚未將索引的實際像素顏色解讀成紅／綠。
- `0x015aaff4` 依修改旗標及 `CloseWithoutAsk` 設定，決定關閉時的保存／不保存／取消提示。

重建時需要保留物件模型，才能支援完成後再次選取、拖移與調整標註。跨重開恢復與每次編輯自動保存仍是使用者對替代程式的要求；本輪沒有證明原版也如此。

## 輸出與快捷鍵設定

- `TfraOptionsAutoSave` 是獨立設定頁；`0x0186f28c` 開啟資料夾選擇器，`0x0186f154` 驗證路徑，`0x0186fb2c` 保存 `Setting/AutoSaveFolder` 與 `UseAutoSave`。
- `TfraOptionsFileName` 提供日期時間、純編號及文字加編號的命名選項；檔案名稱與資料夾設定分開。
- `TfraOptionsHotKeys` 有各模式的快捷鍵欄位與修飾鍵控制項。`0x01875528` 匯集各模式設定；`0x01564ccc` 登記各個全域快捷鍵，保存前先處理原登記及衝突。
- `0x0187b6c4` 是設定視窗確定鍵：依序驗證各頁、定位有錯的頁面、成功後再保存各頁設定。
- `0x01998c70 → 0x0199882c → 0x01abbb30` 是擷取結果的自動輸出路徑；不能由此推論編輯後每次都自動存檔。
