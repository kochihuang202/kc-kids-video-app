# InkBridge 實作流程（使用者確認，2026-10-30）

目標是盡可能忠實重製 FlexNote 的介面、功能、互動與效能；M1/M2 的簡化底座不是最終產品。

執行順序與證據要求以 [docs/DEVELOPMENT_WORKFLOW.md](docs/DEVELOPMENT_WORKFLOW.md) 為準：

1. 有未知、疑點或差距，先查既有 Gemini 清單／REA、原版程式及必要的針對性 REA；不要先猜、先換成自己熟悉的做法。
2. 已查到的原版行為先確認證據，轉成可實作與驗收的規格，再以 InkBridge 自有程式碼重製。不得任意簡化已確認的行為。
3. 只有確認查不到的部分才自行設計補足；先記錄查過的來源、結果、限制與未確認點，將暫定方案和原版事實分清楚。
4. 修改前先重現／建立基準；修改後對照測試與量測。對自己程式的 bug 先做可重現測試，不用沒有證據的原版推論代替診斷。
5. 不重複已證實的完整 REA；復用證據，針對實際缺口補查。Gemini 負責的清單不可未核對就全部標成已完成。
6. 保留獨立可維護原始碼、資料與設定；不直接搬用 FlexNote 專有 JavaScript／二進位，不碰正式 FlexNote 資料。原版程式片段留在私人研究，不推送產品交付分支。

沿用上層回歸、Git 同步與提交規則；只提交本次範圍，不納入同一工作目錄內其他專案的變更。
