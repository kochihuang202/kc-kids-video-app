# InkBridge own sharing service

Cloudflare Pages advanced-mode `_worker.js`, with one **private** R2 binding named `SHARE_BUCKET`. The reader static build is deployed at `/reader/<readerBuild>/`; Pages supplies `ASSETS`. No R2 public domain, r2.dev endpoint, presigned URL, FlexNote account or service is used. `_worker.js` handles every `/api/*` and `/s/*` request and explicitly delegates only `/reader/*` to static assets. Deployment and account resources are managed separately; this directory does not create them.

Secret `BOOTSTRAP_TOKEN_SHA256` contains only the lowercase SHA-256 of a randomly generated administrator bearer token. The administrator token itself belongs in the desktop's local credential store, never in this source tree or generated website. Device tokens are random, only their SHA-256 is stored under `devices/`; delete/revoke that record to revoke a device. Bootstrap token rotation is a secret update. Pairing codes have 128 random bits, expire after five minutes and are atomically consumed once.

## HTTP contract (protocol 1)

Every administrative endpoint requires `Authorization: Bearer <device-token>` except redeem. API errors are JSON `{error}` with HTTP 400/401/404/409/410/422. `409` requires refreshing current status; a rejected publication leaves the previous current version unchanged. Public reads use no credential.

| Method / path | Request | Response |
| --- | --- | --- |
| GET `/health` | — | `{ok:true,service:'inkbridge-share',protocol:1}` |
| GET `/api/shares/status?workspaceId=…&rootBoardId=…` | — | `null` or status below |
| POST `/api/uploads` | `{workspaceId,rootBoardId,requestId,expectedVersion,manifest,selection?,imagePreset?,capturedAt?}` | `{uploadId,publicationId,partSize:8388608,files:[{path,size,sha256,complete,uploadedParts:[{partNumber,etag,sha256}]}]}` |
| PUT `/api/uploads/:uploadId/files/:sha256/parts/:number` | Raw bytes; `X-Part-Sha256` | `{partNumber,etag,sha256}` |
| POST `/api/uploads/:uploadId/files/:sha256/complete` | `{parts:[{partNumber,etag,sha256}]}` in ascending order | `{complete:true,sha256}` |
| POST `/api/uploads/:uploadId/commit` | `{}` | Status |
| POST `/api/uploads/:uploadId/cancel` | `{}` | `{cancelled,committed,status?}`; abort unfinished multipart objects |
| POST `/api/shares/:publicationId/enabled` | `{expectedVersion,enabled}` | Status with new version |
| POST `/api/pairings` | `{}` | `{code,expiresAt}` (Unix milliseconds) |
| POST `/api/pairings/redeem` | `{code}`; no bearer | `{token}` (show/store once) |
| GET/HEAD `/s/:publicationId/` | `?shareId=<boardId>` | Current reader index from `ASSETS` |
| GET/HEAD `/s/:publicationId/share.json` | optional `shareId`, `v` | Current immutable graph plus `publicationVersion` and `publishedAt` |
| GET/HEAD `/s/:publicationId/assets/<file>` | optional `shareId`, `v`; supports `Range` | Current attachment bytes |

Status is `{publicationId,version,enabled,rootBoardId,readerBuild,url,selection?,imagePreset?,capturedAt,publishedAt}`. The stable URL is `/s/<publicationId>/?shareId=<rootBoardId>`. Identity is SHA-256 of the site origin, workspace ID and root board ID (truncated to 160 bits). The existing version must be supplied as `expectedVersion`; first publish uses `null`. Reusing a `requestId` with different package/options fails. Retrying the identical request after commit returns its current successful status.

Wire manifest: `{format:'inkbridge-share-package',version:1,rootBoardId,readerBuild,files:[{path,size,sha256,contentType}]}`. Only `share.json` and `assets/…` are allowed. The graph remains the existing `inkbridge-web-share` v1 format. Every published asset must be in `share.json.attachments`, and every attachment must be in the manifest with the same size and hash. Board and element memberships are checked before changing current. Desktop exporter is responsible for producing the already scoped, privacy-filtered graph.

## Integrity, concurrency and reader behavior

All multipart requests go through the authenticated Worker. Every part is at most 8 MiB (all except the last exactly 8 MiB); bounded stream reads reject larger bodies without materializing the complete request. The Worker checks each part's SHA-256 before R2 upload. Atomic content claims prevent conflicting retries from overwriting a part; separate R2 receipt keys make parallel parts independent. Completion verifies the exact ordered receipts and full length, then streams the completed staging object into `objects/<sha256>` using **R2 `put({sha256: expected})` checksum verification**. R2 accepts the object only when its full received stream matches the expected SHA-256; the Worker additionally checks returned/stored `checksums.sha256` before treating CAS as verified. This keeps the 512 MiB full-file hashing in R2's storage service rather than the publishing Worker's JavaScript isolate. Multipart ETags are receipt identifiers, **never** treated as SHA-256. A failed hash cannot create a verified CAS object or change current.

The desktop streams hashes before upload and re-reads/hashes every source again, including resumed/skipped files, before committing. It uses two concurrent part requests, persists receipts and request identity in an atomic local journal, reconciles with authoritative server receipts on resume, and stops scheduling work on error/cancellation. Network interruption keeps the same request resumable. Explicit cancellation retains the local immutable package/journal but marks the server session cancelled and aborts unfinished multipart objects; publishing that package later uses a new request ID. If cancellation cannot reach the server, its journal records `serverCancellationPending`. No credentials are written to journals. `signal` cancels fetch and prevents commit; an already accepted atomic commit cannot be undone by aborting a local request.

Versions are immutable under `publications/<id>/versions/<version>`. The only mutable publication state is `current`, updated using R2 `onlyIf.etagMatches` (or `etagDoesNotMatch:'*'` for first publish). CAS and uncommitted versions remain private. No endpoint accepts a historical version to bypass current membership or revocation. Every public graph/media read rechecks current, enabled state, selected board and current file membership, and uses `Cache-Control: no-store`. Reader loads graph first, then appends `?v=<publicationVersion>` to asset requests; a changed current returns 409 so it can offer reload instead of mixing versions. Disabled shares return 404 for graph, index and assets.

R2 retains immutable versions and CAS; failed multipart staging and old upload records currently need operator lifecycle cleanup. Do not configure lifecycle deletion of live `objects/` or publication records. PDFs are limited to 512 MiB, images to 64 MiB and the scoped graph JSON to 16 MiB (the graph is parsed before commit). Only declared graph/asset MIME types are served with `nosniff`. Unselected child references are accepted only as geometry/identity plus `isUnshared:true,name:'未分享'`; titles, preview metadata or extra properties on these placeholders are rejected. Full and preview attachment paths/hash/size must both belong to the manifest. Account deployment must measure part-processing CPU and large-file completion on its actual Workers plan: local workerd/R2 tests do not establish free-tier cloud CPU headroom. This implementation does not silently enable a paid plan.

## Desktop API and local verification

`require('../src/main/share-client.cjs').createShareClient({baseUrl,token,jobDirectory})` exposes `status({workspaceId,rootBoardId})`, `publish({workspaceId,rootBoardId,requestId,expectedVersion,packageDirectory,readerBuild?,selection?,imagePreset?,onProgress?,signal?})`, `setEnabled({publicationId,expectedVersion,enabled})`, `createPairing()`, `redeemPairing({code})`, `cancelUpload({uploadId})`, `listJobs()`. Publish reads `package-manifest.json`, supports exporter `bytes` or wire `size`, uploads only graph/assets, and requires reader build from options or manifest. Optional `fetch` injection is used by integration tests; production uses native fetch and requires HTTPS (HTTP only for loopback tests).

Run `node --test inkbridge/tests/share-cloud.test.cjs` from repository root. It runs the actual Worker in local workerd/Miniflare with its R2 implementation, rather than replacing bucket APIs with unit doubles. Inputs are isolated synthetic graph/PDF bytes and a synthetic bootstrap token. This proves local protocol behavior, not deployment, account access, physical browser reading or live Cloudflare performance. Existing scoped-export regression: `node --test inkbridge/tests/web-share-data.test.cjs inkbridge/tests/web-share-export.test.cjs`.

For the optional real 512 MiB fixture, set `INKBRIDGE_TEST_LARGE_SHARE=1` and run only `--test-name-pattern="512 MiB"`. It generates a valid three-page PDF with legal padding, sends 64 PDF parts plus the graph part, validates R2's stored SHA-256 checksum and a real PDF Range response, and records elapsed time/heartbeat. It uses substantial temporary disk and tests the actual local R2 implementation; its whole workerd process includes the local R2 storage service and is not a measurement of a deployed Worker's isolate memory.

`wrangler.toml` binds the dedicated private `inkbridge-share` bucket and expects generated Pages files under `inkbridge/release/share-site`. Before deploying, copy this `_worker.js` into that generated directory and place the independently built reader at `reader/<readerBuild>/`. The parent integration/provisioning tool must create only these dedicated account resources, supply `BOOTSTRAP_TOKEN_SHA256` through Wrangler's secret stdin (never a committed config value), and record the **actual** returned production URL. Example commands from this directory: `wrangler r2 bucket create inkbridge-share`, `wrangler pages project create inkbridge-share --production-branch main`, `wrangler pages secret put BOOTSTRAP_TOKEN_SHA256 --project-name inkbridge-share`, then `wrangler pages deploy ../release/share-site --project-name inkbridge-share --branch main`. These documented commands have not themselves created or deployed account resources.
