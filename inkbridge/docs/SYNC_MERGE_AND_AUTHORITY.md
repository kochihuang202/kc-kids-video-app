# 自動合併與「以這台為準」

依使用者 2026-11-18 確認的設計實作 InkBridge 自有 OneDrive 協定；沿用原版編輯器、白板、設定父介面及原有保存／還原管線。本功能不呼叫 FlexNote 帳號或雲端服務。

## 日常同步

以可驗證的單一共同祖先進行三方比較。不同白板、不同卡片、不同欄位的修改合併；雙方新增的 UUID 實體均保留。同一卡片的文字與富文字文件視為一個欄位，不把兩份 Lexical AST 任意拼接。位置的 x/y 成對處理；原版 instance catalog 的座標鏡像跟隨主資料，避免一個移動重複出現兩項衝突。其餘物件欄位遞迴比較，未知陣列保守視為單一欄位。

版本數字、SQLite 收據、觀看位置不判定內容輸贏；保存時間等衍生資訊不製造文字衝突。相同雜湊的獨立附件匯入合為一份 CAS 記錄；HTML bundle 保留各自相對檔名與 MIME，允許驗證後以同一雜湊取得不同儲存副檔名的相同位元組。

刪除／回收站與另一邊的內容修改、移除位置與另一邊編輯共用卡片，都須明確選擇。合併不得製造斷開的必要關聯、循環白板／群組／思維導圖或同日期的兩筆有效日記。合併結果有兩個來源父節點；已整合的另一個父節點不再視為未處理分支。兩台同時產生相同內容及相同父節點的合併，以驗證後的語意雜湊建立等價關係，後續編輯仍能接續。

共同基準若已被舊版清除，或有多個無法唯一判定的共同基準，不猜測合併。保留資料、說明缺口，提供明確的「以這台為準」選項。新版本以 `sync-devices/<workspace>/<device>.json` 保護各電腦仍需使用的共同基準；同內容不重寫，避免檔案事件形成自我輪詢。其餘備份仍使用原有疏化保留規則；真正未整合的分支保留。

## 逐項選擇

一個可續用的面板呈現白板、卡片、欄位、兩台內容與保存時間；提供上一項、下一項、跳到指定項目，以及本機／另一台選擇。選擇先持久保存於本機，全部處理後才正式套用。按稍後處理或正常重開不會遺失選擇。合併完成前會重新擷取與比較；內容已變更的衝突不得沿用舊選擇直接覆蓋，仍相同的項目可保留選擇。

預覽可能截短，實際套用的是完整欄位。合併前保存雙方版本；原始版本依既有備份保留規則管理，不宣稱永久保存所有舊版。

## 「以這台為準，讓其他電腦對齊」

入口：設定 → 本地存儲與備份 → 指定這台為準。衝突面板另有「整份以這台為準」，啟動等待／衝突畫面也提供入口。按鈕本身就是明確指定，不另加多輪確認。

此操作保存目前工作區完整內容，發布帶有新 `authorityId` 的指定版本；它不把遠端獨有卡片或不重疊修改額外加入本機內容。只有同一已配對工作區會對齊，不改變其他工作區身分。

接收端若尚未採用該指定版本，會先等待所有編輯器 flush／commit、將自己的未同步內容保存為完整備份，再在原視窗載入指定版本或其唯一完整後續版本。舊世代晚到的資料顯示為「指定版本對齊前保留的內容」，不自動混回目前內容。接收後的新編輯繼承該世代，正常同步與三方合併，不反覆重設。使用者若明確還原舊備份，將其當作目前世代的新前進版本。

指定版本按因果父鏈判定，沒有時間優先或電腦名稱優先。兩台未看到對方命令而同時指定時，保留雙方，要求在要採用的電腦再次指定，以一個新命令明確包含兩個來源。版本／附件未到齊先等待；交換區不可用時保留本機待送版本，不假稱已上傳雲端。

兩台都須更新至 0.8.0 才具備此接收與合併行為。OneDrive 尚未下載到本機的版本無法事先被偵測；離線期間的修改在收到指定版本前先備份，不能用不可靠的牆上時間猜測其編輯順序。

## 寫入與回復邊界

使用集中保存佇列、全部視窗的組字／編輯 flush ACK，以及主程序寫入屏障。編輯、附件或新視窗操作若在屏障期間遲到，拒絕寫入並中止替換，保留原視窗草稿，稍後重試。所有資料在獨立 SQLite 暫存檔合併，檢查外鍵、結構與完整 CAS；發布後才走現有原視窗切換與世代 IPC 防護。

失敗回復包括工作資料庫、快照 head 與共同基準資料；不讓回復後的保留策略誤以為已採用新版。沒有 SQLite schema 遷移，仍為 schema 1。

## 測試與證據範圍

維護測試：`workspace-merge.test.cjs`、`sync-merge.test.cjs`、`sync-write-barrier.test.cjs`、`html-merge.test.cjs`；相關舊同步、HTML、附件、分享、快照、保留、排序共 60 項通過。原版 `check-seamless-sync` 的真衝突提示預期依本次明確規格改為逐項確認；其資料保留、組字及 IPC 斷言未弱化。

實際 Electron：`check-auto-merge.cjs` 驗證啟動與原視窗合併、未保存中文、兩項衝突導航、草稿重開、過期選擇拒絕、共同合併後繼續編輯；`check-authority.cjs` 用兩個真實程式及分離的模擬 OneDrive 快取驗證設定按鈕、未知的未同步中文備份、原視窗對齊一次、後續正常雙向接續及正常關閉主視窗。既有還原前最後中文與 HTML／組字同步流程亦通過。

這是隔離資料與模擬傳送延遲的驗證；未操作使用者另一台實機，未測量真實 OneDrive 的傳送速度，未修改正式筆記。封裝與交付收據另見版本發布文件。
