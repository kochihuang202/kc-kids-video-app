# InkBridge：確認來源、優先重用，缺口先討論

使用者於 2026-10-30（Asia/Taipei）較晚明確確認：盡可能完整拷貝／重用既有程式，因為原版有大量細節，自行重寫會造成巨量重工與驗證負擔。重點是改得動、可維護、沒有未解黑盒，而非每行都自行撰寫。**本版取代先前「完全自行撰寫、不搬原模組」及「查不到就自行設計」的規則。**

## 固定順序

**既有研究／Gemini PRD → 原版來源與完整依賴確認 → 優先完整拷貝／重用 → 隔離修改與可重建驗證 → 工程代理自行操作／對照／回歸。**

遇到黑盒：**尋找可能來源 → REA拆解／還原 → 驗證能讀、能改、能重建；確實追不到才列證據與替代方案，先討論再決定。** 不得自行跨過確認階段開始另寫一套。

### 先確認

遇到操作、功能、資料或效能上的疑點，先找既有分析、切片定位、版本／hash、原版使用者流程及 Gemini 證據。已有充分證據就沿用；不足才做範圍明確的靜態 REA，必要時在安全隔離環境觀察原版 runtime。不啟動會接觸正式 profile 的原版來「試看看」。

查到模組或 API 名稱只證明存在，還要確認條件、輸入輸出、狀態切換與例外；程式機制不等於量測效能。功能清單與研究報告也可能有錯，必須交叉核對，不能因另一個模型寫了就直接接受。

### 優先完整拷貝／重用

將原版行為轉成規格：使用者觸發、正常結果、保存邊界、取消／失敗行為，以及可重複的驗收方式。介面、手勢、快捷鍵、編輯與白板切換等都屬於目標，不能只保留相似技術名詞。

能完整取得且確認可用、可修改的原模組與必要依賴，優先拷貝／重用；不能因為不是自己寫的就排除，也不能只挑幾個參數／簡化行為便宣稱等效。追清生命週期、狀態、資料格式、例外、IPC與資源依賴，再做最小修改。

使用者於2026-10-31再次確認：目標是porting FlexNote，不能把原子元件嵌入自製父殼就宣稱整段移植完成。每個介面區域須核對原父元件、依賴狀態、完整入口／事件鏈及實際畫面；資料保存測試通過不等於外觀與操作驗收。PRD與使用者實際截圖／同版原碼不符時，記錄差異並以後者確認，不沿用過期的自製布局。未移植的外殼必須明列，不能作為已完成porting交付。

「獨立」指能獨立執行、有自己的資料／設定、能修改重建與維護，不代表來源必須全部自寫。可讀打包JS仍可能缺少型別、原檔結構、建置設定；必須列出缺失並驗證，而不是直接宣稱已拿到完整開發專案。

原生／WASM先找匹配版本的公開原碼與建置鏈，找不到的部分做針對性REA。反編譯結果要轉成可解釋、可測、可修改的實作；保留原版EXE或不明模組只供呼叫，不算黑盒已拆完。既有副本、研究及重用候選保持隔離，不碰正式資料；保留不得繞過授權保護／完整性機制、不公開散布原版專有內容的限制。自寫程式、patch、測試與安全的研究結論由Git追蹤。

### 確實查不到，先提出討論

「查不到」不能是尚未查、工具暫時失敗、只搜了一個名稱，或實作不方便。記錄實際查過的來源／模組／範圍、結果、存取或版本限制，說明哪些細節仍無法確認。無須為此無限制重做整份逆向，但不能憑空宣稱已查清。

在該功能紀錄中分列：原版已知事實、已查來源與結果、未確認點、無法繼續追查的具體原因、可選替代方案、影響與驗證成本。**先和使用者討論後才決定是否自行實作或改變設計。** 尚未討論前保持待查，不得先加入暫定fallback、簡化功能、換演算法或跳過模組。

歷史上已加入但沒有原版證據的fallback（例如一般長文caret自動移動畫布）不是往後自行設計的許可；必須列為來源缺口供討論。

### 驗證差距

使用者於2026-10-30補充：只跑本次改動相關的針對性測試，不要每次整個全部重測。先列出修改的使用者流程、直接呼叫鏈與相關歷史回歸，再選測試；未改動的功能不納入。共用文字排版變更只抽查有關的Canvas資源／密集文字渲染場景，不以「共用模組」為由一律重跑全部白板場景。封裝版也沿用相關測試子集；只有新失敗或新修改影響範圍時再擴大，不重複已通過而未受影響的檢查。

修改前保留 Git 基線、相關歷史回歸及必要效能結果。自己程式的 bug 先重現，再用實際呼叫邊界測試與量測定位原因；只有原版行為未知才補相應 REA，不靠猜測修程式。

修改後區分：單元／合成測試、真實 Electron／封裝版操作、原版 runtime 對照，以及尚未驗證。範圍、場景、樣本、版本與 hash 可追溯；未量測不宣稱性能相同，不把框線對齊說成全部文字排版完全一致。測試通過才標示該驗收項目完成；仍有差距就明列。

工程代理負責自己開啟、操作與檢查畫面，測真實長文／格式／語法／貼上、保存重開及歷史回歸，不只做簡短fill()或查AST。不得讓使用者當主要測試人員，替任意自行重寫承擔驗證成本；只有確實無法自行取得的硬體／帳號／物理輸入驗證，才具體列出需要協助的最小項目。

## 本次已知差距的示例

- 密集 500 卡連續縮放仍掉幀：已有 raw timing／record／flush 證據，整個長停頓的成因尚未全部確認。下一步先 profiler 並對照相關 REA，不直接套用整批雙層重寫。
- 公開 Lexical 的可選 undefined 欄位造成 JSON 拒絕：以真實編輯器輸出和 SQLite 回歸確認，修正 JSON 邊界；沒有把它誤歸因為 FlexNote REA 不足。
- Gemini 功能清單仍在整理：保留草稿，不把其中「DONE」或範圍排除直接當成使用者已驗收／新指令；逐項對照 InkBridge 原始碼和測試。

本流程不取消既有快照／資料自主目標，也不在 M2 擴展 OneDrive 或完整快照 GUI；功能順序後續根據已確認的原版清單與使用者優先級安排。
